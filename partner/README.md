# 파트너

옵시디언 볼트에 뿌리내린 사고 파트너. 로컬 웹 UI로 대화하고, 볼트를 기억으로 쓴다.

비서가 아니라 파트너다. 볼트를 먼저 읽고 답하고, 근거가 된 노트를 밝히고,
논리에 구멍이 보이면 지적한다.

## 왜 볼트가 기억인가

보통 에이전트 기억은 벡터DB나 SQLite에 쌓인다. 그러면 사람이 못 읽고 못 고친다.
볼트를 쓰면 기억이 그냥 마크다운이라 직접 열어서 고치고 지울 수 있고, 이미 걸어둔
`[[위키링크]]`가 그대로 지식 그래프가 된다. 임베딩 인덱스를 따로 만들 필요가 없다.

기억을 새로 만드는 게 아니라, **이미 쌓인 기억에 접근권을 주는** 구조다.

## 빠른 시작

```bash
cd partner
npm install
cp config.example.json config.json   # vaultPath를 본인 볼트 루트로 수정
npm run build
npm start
```

http://localhost:7717 접속.

환경변수로도 덮어쓸 수 있다: `VAULT_PATH`, `PROJECT_PATH`, `PORT`, `MODEL`.

```bash
VAULT_PATH=~/Documents/MyVault npm start
```

## 설정

| 키 | 설명 | 기본값 |
|---|---|---|
| `vaultPath` | 볼트 루트 절대경로. `~` 가능 | (필수) |
| `writeRoot` | 파트너가 쓸 수 있는 유일한 폴더 | `Partner` |
| `ignore` | 인덱싱에서 뺄 폴더 | `.obsidian`, `.trash`, `.git`, `node_modules` |
| `projectPath` | 코드 작업을 할 레포 경로 | (없음) |
| `port` | 웹 UI 포트 | `7717` |
| `model` | 사용할 모델 | `claude-opus-5` |
| `userName` | 파트너가 부를 이름 | (없음) |
| `personaExtra` | 페르소나에 덧붙일 설명 | (없음) |

## 볼트 도구

파트너는 in-process MCP 서버로 이 도구들을 쓴다.

| 도구 | 하는 일 |
|---|---|
| `vault_search` | 키워드·태그·폴더 검색. 한국어 부분일치 지원 |
| `vault_read` | 노트 전문 + 프론트매터 + 링크 + 백링크 |
| `vault_neighbors` | 링크 그래프 탐색 (1~2홉). 키워드보다 정확한 연관성 신호 |
| `vault_recent` | 최근 수정 노트 |
| `vault_map` | 볼트 구조 — 폴더, 태그 분포 |
| `vault_write` | 노트 생성/추가. **`writeRoot` 안에만** |

### 한국어 검색

한국어는 어간과 조사 사이에 공백이 없다. 그래서 단어 경계 매칭을 쓰면 `볼트`로
`볼트에서`를 못 찾는다. 부분일치로 검색하는 이유다.

### 코드블록 안의 `#`은 태그가 아니다

`#!/bin/sh`, `#include`, `#define` 같은 게 태그로 잡히면 태그 목록이 오염된다.
인덱서가 펜스 코드블록과 인라인 코드를 먼저 걷어내고 태그를 뽑는다.

## 안전장치

- **쓰기는 `writeRoot` 안에서만.** 기존 노트는 어떤 경우에도 덮어쓰이지 않는다.
  경로 탐색(`../`), 정규화 후 탈출(`Partner/../Dev/x.md`), 접두어가 겹치는
  형제 폴더(`Partnerish/`)까지 전부 막혀 있고 테스트로 고정돼 있다.
- **`create` 모드가 기본.** 같은 이름이 있으면 실패한다. 덮어쓰려면 명시해야 한다.
- **도구 화이트리스트.** 볼트 도구와 읽기 전용 내장 도구만 허용된다.
  `Bash`, `Write`, `Edit` 는 거부된다.
- **서버는 `127.0.0.1`에만 바인딩된다.** 외부에서 접근할 수 없다.
- **모델 출력은 렌더링 전에 전부 이스케이프된다.** 마크업 주입이 불가능하다.

## 동작 방식

```
브라우저 ──POST /api/chat──> node:http 서버
                               │
                               ├── Conversation (세션 resume)
                               │     └── Agent SDK query()
                               │           ├── 볼트 MCP 도구 6종
                               │           └── 읽기 전용 내장 도구
                               │
                               └── NDJSON 스트림 ──> 브라우저
                                     delta / tool / cite / error / done
```

- **세션 기억**은 Agent SDK의 `resume`이 담당한다. 대화 내역을 직접 다시
  보내지 않아도 스무 턴 전 얘기를 기억한다.
- **인용**은 도구 핸들러가 노트를 꺼낼 때마다 기록된다. UI에서 클릭하면
  `obsidian://` URI로 옵시디언에서 바로 열린다.
- **볼트 감시**가 켜져 있어서, 옵시디언에서 방금 저장한 노트를 파트너가
  같은 대화 안에서 바로 읽는다. (재인덱싱은 700ms 디바운스)

## 알려진 한계

- 인덱스는 메모리에 통째로 올라간다. 노트 수천 개까지는 문제없지만
  수만 개 규모라면 증분 인덱싱이 필요하다.
- 대화는 서버 프로세스 메모리에 있다. 서버를 재시작하면 새 대화로 시작한다.
  (볼트에 남긴 노트는 당연히 남는다.)
- 프론트매터 파서는 옵시디언에서 흔한 형태 — 스칼라와 문자열 리스트 — 만
  다룬다. 중첩 구조는 문자열로 보존되고 버려지지는 않는다.
- 재귀 파일 감시를 지원하지 않는 플랫폼에서는 시작 시점 인덱스로 고정된다.
